# Small Correct Diff

日本語 | [English](README.md)

**AIが書くコードを、コードゴルフにせず小さく保つためのCodexプラグイン兼ポータブルAgent Skillです。**

コーディングエージェントは、ときどき依頼に必要な範囲を超えて実装します。新しいヘルパーやレイヤー、依存関係、将来を見越した設定、広範なリファクタリングなどです。Small Correct Diffは、エージェントに次の優先順位を与えます。

> **正しさ → 安全性 → 既存設計との整合性 → 単純さ → 差分の小ささ → コード行数**

目的は最短のコードを書くことではありません。**正しく、完全な変更を可能な限り小さくすること**です。

## 何をするものか

コードを追加する前に、エージェントは次の順番で確認します。

1. そもそも実装する必要があるか
2. リポジトリ内に再利用できるものがないか
3. 標準ライブラリで解決できないか
4. プラットフォーム標準の機能で解決できないか
5. 導入済みの依存関係を再利用できないか
6. 新しい抽象化を作らず、直接かつ明確に実装できないか
7. それでも必要な場合だけ、最小限のコードを追加する

バグ修正では、報告された症状だけにパッチを当てるのではなく、呼び出し元と処理の流れを調べて根本原因を直すよう指示します。

## 小さくするために削ってはいけないもの

Small Correct Diffでは、以下をコードの短さより優先します。

- 正しさと完全性
- セキュリティと認可
- データの整合性
- 信頼境界でのバリデーション
- データ損失や破損を防ぐエラー処理
- 必要な並行処理・トランザクション保証
- アクセシビリティ
- 明示的に依頼された動作

小さくても間違ったパッチは、少し大きくても正しいパッチより劣ります。

## Codexへのインストール

このリポジトリをプラグインMarketplaceとして追加し、プラグインをインストールします。

```bash
codex plugin marketplace add matcha-gumii/small-correct-diff
codex plugin add small-correct-diff@small-correct-diff
```

インストール後はCodexを再起動し、新しいタスクを開始してください。

## その他のAgent Skills対応クライアント

`skills/small-correct-diff` を、利用するエージェント環境のSkill配置先へコピーしてください。`SKILL.md` の `name` と一致させるため、ディレクトリ名は `small-correct-diff` のままにします。

特定のCodexプロジェクトで常にこの方針を適用したい場合は、`AGENTS.md` を対象リポジトリのルートへコピーします。すでに `AGENTS.md` が存在する場合は上書きせず、プロジェクト固有の指示と統合してください。

## 構成

```text
small-correct-diff/
├── .agents/plugins/marketplace.json
├── .codex-plugin/plugin.json
├── skills/small-correct-diff/SKILL.md
├── AGENTS.md
├── README.md
├── README.ja.md
└── LICENSE
```

マニフェストと `skills/` の配置は、ChatGPTとCodexで共通の現行プラグイン形式に合わせています。`AGENTS.md` は、必要に応じてプロジェクト全体へ常時適用するポリシーなので、Skillとは分けています。

## 向いている用途

機能実装、バグ修正、リファクタリング、依存関係の判断、コードレビュー、AIが生成するPull Requestの差分を必要な範囲に保つ作業に向いています。

一方、探索、アーキテクチャのブレインストーミング、使い捨てのプロトタイプ、複数案の生成自体が目的の場合には、あまり向いていません。

## トークン使用量について

差分が小さくなることで、生成コード量やトークン使用量、コスト、処理時間が減る可能性はあります。ただし効果はモデルやタスクによって異なります。このプロジェクトでは独自ベンチマークをまだ公開していないため、具体的な削減率は主張していません。

## 着想元

このプロジェクトは、YAGNI、既存コードの再利用、標準ライブラリやネイティブ機能の優先、過剰設計を避けるという[Ponytail](https://github.com/DietrichGebert/ponytail)の考え方から着想を得ています。

Small Correct Diffは、優先順位を意図的に変更した独立実装です。差分やコード行数を減らすことより、正しさ、安全性、既存アーキテクチャとの整合性を優先します。Ponytailプロジェクトとの提携や、同プロジェクトによる推奨を受けたものではありません。
